# Professional Workflow V2

Модернизирован существующий Professional Workflow. Standard и backend не менялись. Переключение Standard → Pro показывает чёрный экран с тремя последовательно пульсирующими точками в течение 2000 мс, затем Canvas плавно появляется. Таймер очищается при переключении и размонтировании; заголовок с выбором режима остаётся доступен.

Нижняя форма PromptComposer заменена плавающей стеклянной панелью Models / Prompt / Image / Video / Audio / Start. Audio и Start отключены с подсказкой Coming soon. Models переключается своей кнопкой: крестика нет, выбор модели и клики вне списка его не закрывают. Prompt имеет отдельное состояние и по-прежнему закрывается по Escape, клику вне popover и крестиком. При одновременном открытии Prompt располагается выше Models. Prompt поддерживает Add и Ctrl/Cmd+Enter; пустой текст не добавляется.

Работают узлы:

- `prompt`: текст, редактирование, перемещение, удаление.
- `image`: JPG/JPEG/PNG/WEBP до 10 МБ, миниатюра и имя файла.
- `video`: MP4/WEBM до 50 МБ, превью с ручным воспроизведением. Скрытые и удалённые превью останавливаются, все видео автоматически не запускаются.
- `model`: собственные режим и настройки из `/api/models`. Можно добавить несколько экземпляров одной модели с независимыми параметрами.
- `audio`: тип зарезервирован; создание пока отключено.

У каждого нового узла есть `id`, `type`, `position`, `data`, `configuration`. Панорамирование и масштабирование используют прежнюю систему координат InteractiveCanvas. Новые узлы появляются в видимой области; при наличии места выбирается свободный слот, при заполнении области применяется небольшое смещение. Если карточка не помещается на мобильном экране при текущем масштабе, масштаб уменьшается вокруг центра viewport. Поля ввода, dropdown и медиаплееры исключены из перетаскивания доски. Выбранная карточка поднимается над остальными.

Models представляет горизонтальный popover шириной до 400 px и высотой содержимого 70 px. Края списка плавно исчезают через mask-image, без состояния React на каждый пиксель скролла. Работают колесо, drag-to-scroll мышью и touch swipe; перетаскивание не выбирает модель. Источник — существующий `/api/models`: показываются включённые модели с режимами. `available` в backend зависит от готовности Higgsfield к генерации; он больше не блокирует редактирование графа и добавление узлов. Пустой каталог, отсутствие активных моделей, ошибка API и некорректный ответ показывают отдельные сообщения.

Каждый клик или короткое касание добавляет новый Model Node с уникальным UUID и параметрами каталога, включая повторные экземпляры. Генерация не запускается. Список остаётся открытым. Сохранение использует существующее состояние доски и localStorage: узлы восстанавливаются после смены секции и перезагрузки. Анимация Model Node использует opacity и индивидуальный CSS translate, сохраняя inline transform с координатами Canvas.

Models показывает только круглые иконки. Для Kling и Seedance используются локальные логотипы; для SOUL — существующий логотип Higgsfield. Локальных логотипов Qwen, Ideogram, Recraft, Grok и Wan в проекте нет: используется первая буква названия. Ошибка загрузки логотипа также заменяет его буквой. Полное название доступно в Tooltip при hover/фокусе и в заголовке созданного узла на телефоне. Tooltip вынесен из области скролла и маски через portal, чтобы его не обрезало. Hover/lift, свечение и нажатие включены только при `(hover: hover) and (pointer: fine)`; сенсорные устройства используют нативный `touch-action: pan-x` без hover/active-анимаций. Учитывается prefers-reduced-motion. Для Models отключён backdrop-filter.

## Хранение и загрузки

Состояние расширяет прежний `betelgeuse:board:<userId>` в localStorage: новые nodes, viewport и список скрытых карточек истории. Существующие positions/connections сохраняются при чтении старой доски. Старые connections не выполняются и не отображаются; создание новых связей не реализовано. Доска сохраняется с задержкой 250 мс и при уходе со страницы.

Бинарные файлы размещаются в IndexedDB `betelgeuse:workflow-assets`, отдельно от JSON доски. SHA-256 содержимого вместе с ID пользователя позволяет повторно использовать один файл для нескольких узлов. Изображения загружаются через прежний `POST /api/uploads`, MP4 — через прежний `POST /api/uploads/references`. Подтверждённый upload ID сохраняется; переключение режима и перезагрузка не повторяют загрузку.

WEBM хранится и показывается локально: существующий backend принимает только MP4. Его будущая отправка провайдеру потребует отдельной проверки и расширения backend. Ошибка загрузки изображения/MP4 сохраняет локальное превью и позволяет повторить загрузку вручную. Временные Object URL освобождаются при удалении и размонтировании превью. После удаления последнего узла файла удаляется локальная копия; серверный API удаления загруженных файлов не добавлялся.
